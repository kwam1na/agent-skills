# Hosted delivery lane rules

Use the installed linear-v2.3.0 run-delivery commands and your assigned lane worktree. This is not the installed source: edit skills/, never .agent-skills/. You are not alone; preserve other lanes and lead edits. Own only your current granted files. No lane runs a full suite.

The canonical plan is authoritative for protocol, public projection, watcher ownership, credential handling and test scenarios. Start named tests before implementation. Keep shared JSON schemas/fixtures compatible between Python and Worker. Define the protocol through the public-projection story, then ingestion; uploader and UI can run in parallel only after their declared blockers merge.

Each releasable corpus change includes its catalog/profile/output-list edits and writer-refreshed digests, so source validation passes at every candidate. The lead owns .agents/orchestration.json check-catalogue additions and final integration. New modules must have selectable catalogue IDs before lead acceptance.

Reviews: declare the standard four-round delivery bound, run the two mandated lenses, and add risk-relevant security/API/reliability reviewers as needed; do not manufacture review evidence. Review prepared checkouts independently and reduce actual results. Aim to close all actionable in-contract notes rather than defer. Collect findings before fixing and rerun affected proof once.

Push/open draft PR/handoff only through run-delivery; no lane merges, tags a release, deploys production, rewrites the delivery file, or changes final tracking state. Product deployment and release are lead-owned after evidence. Give the lead head, PR, owned files, proving checks, risks and complete review result.
